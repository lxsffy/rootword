# 第 1 章 产品定位与目标用户

## 1.1 一句话定位

> **RootWord（中文名：词根单词）是一款面向初中生的极简单词背诵工具：用艾宾浩斯间隔重复决定"今天该复习哪几个词"，用词根词缀拆解回答"这个词为什么是这个意思"。**

三个关键词定义了这款产品，也定义了它的边界：

| 关键词 | 含义 | 反面（明确不做） |
|---|---|---|
| **极简** | 打开 3 步内开始学习；单次会话 5 分钟可结束 | 不做社区、商城、课程、直播、游戏化养成 |
| **科学** | 复习时间完全由 SM-2 算法排定，不由用户"感觉"决定 | 不做"顺序刷词表""全部重来"等反遗忘规律的模式 |
| **拆解** | 每个词都能看到前缀/词根/后缀的色块拆解与拼装含义 | 不做纯图片联想、谐音梗为主的学习方式 |

## 1.2 目标用户

### 1.2.1 主要用户：初中生（12–15 岁）

| 维度 | 描述 |
|---|---|
| 身份 | 七年级至九年级在读学生，英语成绩中等及偏上，有明确的"要背单词"的任务感（课内听写、单元测、中考） |
| 词汇量 | 按《义务教育英语课程标准（2022 年版）》五级通行口径，初中阶段目标词汇量约 1600 词；用户实际掌握量通常低于目标量 |
| 设备 | 学生用 iPhone（常见为旧机型，如 iPhone 7/8/X/SE 系列），系统版本偏低（iOS 15.x 常见），本次交付即为该环境服务 |
| 数字素养 | 熟练使用手机，但对"要自己配置的软件"（Anki 类）零耐心，不愿读说明书 |
| 核心痛点 | ① 背了就忘，不知道该什么时候复习；② 死记硬背字母串，找不到规律，重复抄写效率低；③ 背单词 App 太"重"——广告、打卡、社交、课程推销，注意力被抢走 |
| 使用场景 | 课间 5 分钟、晚自习前 10 分钟、睡前躺床上；单手竖屏操作；可能无网络（学校 Wi-Fi 不可用） |

### 1.2.2 次要用户

| 角色 | 诉求 | 在本产品中的体现 |
|---|---|---|
| 家长 | 想知道孩子有没有在背 | 统计页的"连续天数 / 已掌握词数"可一屏说清，不做家长端 App |
| 英语老师 | 下发单元词表 | 提供**导入格式规范**（第 8 章），老师可发送 `.csv/.txt` 词表，学生导入即用 |
| 使用者本人（高阶） | 自己从教辅抄词、从 Excel 整理词表 | 支持粘贴导入 + 文件导入，容错解析 |

### 1.2.3 用户使用姿势（设计约束的来源）

- **单手持机、拇指操作**：主要操作热区必须落在屏幕下半部，因此评分按钮放在卡片下方拇指区，顶部不放高频操作。
- **碎片时间**：任一次学习会话可随时中断——退出后进度自动保存，下次进入"继续学习"。
- **可能无网**：全部功能离线可用，发音使用系统 TTS（离线语音）。
- **旧设备性能有限**：不做高频动画与大量图片，列表使用轻量视图。

## 1.3 量化目标（SMART）

以下为**设计目标**（非实测值），用于第 2 章功能取舍与后续验收：

| # | 目标 | 具体指标 | 衡量方式 |
|---|---|---|---|
| G1 | 上手成本极低 | 冷启动 → 开始学习 ≤ **3 步点击**；首次启动到进入首张卡片 ≤ **60 秒** | 界面走查 + 埋点计数（无埋点时人工走查） |
| G2 | 单次学习时长可控 | 单张卡片平均耗时 ≤ **15 秒**；20 张卡片会话 ≤ **5 分钟** | 会话计时统计 |
| G3 | 记忆效果可验证 | 首次学习后 **24 小时**复习正确率（评分 ≥ "模糊"）≥ **85%** | 复习队列评分记录 |
| G4 | 长期积累 | 日均使用 **10 分钟**，连续 30 天累计"已掌握"（复习间隔 ≥ 21 天）≥ **300 词** | 统计页掌握度口径 |
| G5 | 留存 | 次日留存 ≥ **70%**，7 日留存 ≥ **40%** | 本地启动记录（本机统计，无云端） |
| G6 | 性能（设计目标，未实测） | 3000 词词库下：冷启动 ≤ 1.5 s，会话切换帧率稳定 60 fps，导入 1000 词 ≤ 2 s | Instruments 实测 |

> 口径说明：G1–G5 为产品设计目标；G6 为性能设计目标，**未经真机实测**，数值用于约束实现方式（如不用重量级列表、索引化持久化）。

## 1.4 竞品立场与差异

| 产品 | 优势 | 对本产品的启示 | RootWord 的取舍 |
|---|---|---|---|
| 百词斩 | 图片联想记忆、词库全 | 视觉记忆有效，但图片联想对初中生易"记图不记词" | 用**词根拆解**替代图片联想，形成可迁移的构词能力 |
| 墨墨背单词 | 记忆曲线算法成熟、口碑好 | 算法是核心壁垒，必须科学 | 采用公开的 **SM-2** 算法并显式公开公式，不黑盒 |
| Anki | 完全自由、支持导入 | 自由度=配置成本，初中生不会用 | 保留"可导入"，但**取消**牌组模板/参数配置，参数仅 4 个开关 |
| 各类打卡类 App | 社交激励强 | 激励越强越容易"为打卡而打卡" | 只保留本地连续天数，**不做**分享、排行、金币 |

**结论（论断）**：在初中生这一人群上，"少做"比"多做"更难被模仿——竞品的每一个附加功能都在提高使用门槛。RootWord 的全部竞争力来自两点：**复习时机绝对正确**、**单词可以拆开理解**。

## 1.5 本章小结

- 用户是手持旧 iPhone、只有 5–10 分钟碎片时间、不知道该怎么安排复习的初中生。
- 成功标准被量化为 6 条指标，其中 G1（3 步进入学习）与 G3（24 小时正确率 ≥85%）是两条硬指标，任何功能取舍不得损害它们。
- 差异化来自科学的复习排期与词根拆解，而非功能数量。

# 第 2 章 核心功能取舍

## 2.1 取舍原则

功能准入必须同时满足三条，否则不进入首版：

1. **直接服务于"记住单词"**——不能直接减少遗忘或提升理解的功能一律不进；
2. **零网络、零账号、零第三方依赖**——TrollStore 环境无正式签名与推送通道，任何依赖服务端的功能都是不稳定源；
3. **不增加"进入学习"的步数**——任何让首页变重的功能一律不进。

## 2.2 MVP 功能清单（8 项，按优先级）

| 优先级 | 功能 | 一句话说明 | 支撑目标 |
|---|---|---|---|
| P0 | **今日任务** | 一屏看清今天要学的新词数与到期复习数，一个按钮开始 | G1、G2 |
| P0 | **学习会话** | 卡片翻转 → 三档评分（忘记/模糊/记得）→ 自动排下一次复习 | G2、G3 |
| P0 | **间隔重复引擎（SM-2 变体）** | 纯函数算法，决定每个词的 `dueDate` | G3、G4 |
| P0 | **词根拆解展示** | 卡片背面以三色色块展示 前缀/词根/后缀 与拼装含义 | G3（理解型记忆） |
| P0 | **单词导入** | 支持文件（txt/csv/json）与粘贴导入，容错解析 + 预览确认 | 教师/家长/自学者词表落地 |
| P1 | **词单管理** | 多词单、重命名、删除、词单内搜索与排序 | 支持"单元词表"这类多批次学习 |
| P1 | **词根库** | 预置约 120 条高频词根词缀，可查释义、例词、同根词 | 让"拆解"变成可探索的知识网络 |
| P1 | **学习统计与设置** | 连续天数、掌握度分层、日历热力图；4 个可调参数 | G4、G5 |

## 2.3 明确不做清单（8 项，含理由）

| 不做项 | 理由 |
|---|---|
| 账号体系 / 云同步 | TrollStore 环境无签名与推送通道，且账号体系会要求网络；数据留在本机，用"导出 JSON"满足备份诉求 |
| 在线词典 / AI 生成例句 | 网络依赖 + 不可控成本；释义与例句改为"导入时自带"或"本地词根库拼装" |
| 社交、排行、打卡分享 | 会让学生为"打卡"而非为"记住"使用；且分享必须依赖系统分享面板与网络 |
| 游戏化养成（宠物/金币/皮肤） | 与"极简"直接冲突，且对自控力较弱的初中生易产生反向激励 |
| 图片联想 / 谐音梗主模式 | 词根拆解是可迁移的构词能力，图片联想是单点记忆；两者同时做会稀释记忆路径 |
| 语音识别 / 发音打分 | 需要网络模型或大型离线模型，且评判不稳定，容易打击信心 |
| 多端（iPad / Web / 安卓） | 首版只交付 iPhone 竖屏，避免适配成本摊薄打磨深度 |
| 单词列表"顺序刷词"模式 | 与间隔重复冲突：顺序刷词会产生大量"已会"的无效重复，违背 G3 |

## 2.4 闭环验证：极简是否仍能完成"背单词"？

论断：**能，且必须**。背单词闭环只需三个动作——**看到词 → 判断会不会 → 决定何时再见**。用表格逐项核对闭环完整性：

| 学习闭环环节 | 承载功能 | 若缺失会怎样 |
|---|---|---|
| 确定今天学什么 | 今日任务（新词 + 到期复习队列） | 用户需自己选词，决策成本高，G1 失守 |
| 看到词并回忆 | 学习会话正面（单词 + 音标 + 发音） | 无法形成"主动回忆"，记忆效率下降 |
| 得到正确答案 | 卡片翻转背面（释义 + 例句） | 无法自我校验 |
| 理解为什么 | 词根拆解 + 记忆法文案 | 退化为死记硬背 |
| 反馈记忆强度 | 三档评分 | 算法失去输入，无法排期 |
| 排定下次复习 | SM-2 引擎 | 遗忘曲线失守，G3 失守 |
| 看到长期进展 | 统计页（掌握度、连续天数） | 初中生缺少正反馈，G5 失守 |
| 学自己的词 | 导入 + 词单管理 | 无法覆盖课内词表，产品只能"玩一下" |

八项 P0/P1 功能与八个闭环环节一一对应，无缺口；被砍掉的 8 项功能均不落在闭环上。

## 2.5 参数极简化设计

设置项**只有 4 个**（多于 4 个即视为设计失败）：

| 设置项 | 可选值 | 默认值 | 对算法的影响 |
|---|---|---|---|
| 每日新词上限 | 5 / 10 / 15 / 20 | 10 | 决定每日新词队列长度 |
| 每日复习上限 | 20 / 50 / 100 / 不限 | 100 | 决定复习队列截断阈值 |
| 发音口音 | 美音 / 英音 | 美音 | 仅影响 TTS 音色选择 |
| 震动反馈 | 开 / 关 | 开 | 仅影响触觉反馈 |

固定不可调（避免用户破坏算法效果）：到期排序规则、三档评分映射、间隔上限 180 天、重插上限 2 次/日。

## 2.6 本章小结

- 首版 8 项功能，全部落在学习闭环上，逐项标注了支撑的量化目标。
- 8 项功能被明确排除，每条给出技术或产品层面的理由，其中"顺序刷词模式"的排除是算法正确性的必要选择。
- 设置项被压缩到 4 个，算法关键参数不可调，以保证 G3 的稳定性。

# 第 3 章 信息架构

## 3.1 为什么是 4 个 Tab

论断：**一级区域的数量由"用户心智中的任务数"决定，而非功能数**。初中生使用这款 App 时只存在四种意图：

| Tab | 用户意图 | 为什么不可合并 |
|---|---|---|
| 今日 | "我现在要背单词" | 唯一高频入口，必须占据第一个位置且不承载任何浏览型内容 |
| 词单 | "我要看看有哪些词、要导入自己的词表" | 管理型意图，与"立刻开始学习"的心智冲突，不能混在首页 |
| 词根 | "我想搞懂这个词根" | 探索型意图，是本产品的差异化价值，若藏进"我的"会使其不可发现 |
| 我的 | "我学得怎么样 / 调设置" | 低频但必要，承载统计与设置 |

若减为 3 个 Tab（去掉"词根"），则词根库只能从单词详情二级进入，用户主动探索词根的路径变长，"拆解"这一核心价值的可发现性受损；若增为 5 个，则会为"统计"独立开 Tab，导致用户被数据激励而非被学习驱动。

# 第 4 章 页面流程图

## 4.1 主流程一：首次启动（目标 ≤60 秒进入首张卡片）

```text
[安装后首次打开]

   ↓ wordCount == 0
P02 首次引导（3 屏，横滑或点"继续"）

P08 词单列表（空状态）
   ↓ 点"导入单词"

   ↓ 解析成功

   ↓ 点"确认导入 N 个词"
P12-成功（Toast + 按钮变为"去学习"）
```

**步数核对**：从 P01 到 P04 共 4 屏，其中"引导 3 屏"可一次性跳过，跳过路径为 **P01 → P02-跳过 → P08 → P12 → P12-预览 → P03 → P04**；最短路径（已导入词后重装）为 **P01 → P03 → P04 = 3 步点击**，满足 G1。

## 4.2 主流程二：日常学习（核心循环）

```text
P03 今日任务
   ↓ 点"开始学习（新词 10 · 复习 23）"
P04 卡片正面 —— 显示单词 / 音标 / 发音按钮 / 底部长按提示
   ├─ 点"显示答案" 或 上滑卡片
   ↓
P05 卡片背面 —— 释义 / 词根三色拆解 / 例句
   ├─ 点【忘记】q=1 → 该词 10 分钟后重插今日队列（每日至多 2 次）
   ├─ 点【模糊】q=3 → 间隔 ×0.6 档
   └─ 点【记得】q=5 → 按 SM-2 正常推进
   ↓ 评分后：卡片 0.28 s 右滑出，下一张推入
   ↓ 队列空
P06 会话完成 —— 本次学了 N 张 / 用时 M 分 / 正确率 P%
   ├─ 点"再来一组" → 若队列仍有剩余则回到 P04，否则 Toast"今日任务已完成"
   └─ 点"完成" → P03（首页进度环填满，文案变为"今日已完成"）
```

**步数核对**：从打开 App 到第一张卡片 = **Tab1 默认停留 + 1 次点击**，满足 G1/G2。

### 4.2.1 会话中的三个分支

```text
用户点右上角"×"（退出会话）
   ↓
C03 退出确认弹窗
   ├─ "继续学习" → 回到 P04（当前卡保持不变）
   └─ "退出" → 保存进度 → P03（进度环显示未完成）
        └─ 下次进入 P03，主按钮文案变为"继续学习（还剩 12 张）"

用户切到后台（来电 / 锁屏）
   ↓ 自动保存当前队列与答题进度（无弹窗、无中断提示）
返回前台 → 停在原卡片原位，不重排、不跳题

今日队列中出现重复词（因"忘记"重插）
   ↓ 同一词第二次出现时，卡片顶部显示黄色小标签"今日第 2 次"，卡片外观不变
```

## 4.3 主流程三：复习（间隔到期）

```text
P03 今日任务 —— 复习 23 张（到期词）
   ├─ 若同时存在新词与复习：先复习（复习在前，避免到期债累积），新词在后
   ├─ 复习上限截断：超过设置的"每日复习上限"时，只取最旧到期的前 N 个
   └─ 点"开始学习"
P04/P05 同日常学习循环
   ↓
P06 完成页 —— 额外展示"已推到未来的词：41 张（最近一次 3 天后）"
```

**到期债处理规则**（写死在算法内，用户不可见）：
- 到期词按 `dueAt` 升序，最旧优先；
- 逾期 > 2 倍原间隔的词，先降档（`interval × 0.5`、`reps - 1`）再进入队列，避免"假装记得"；
- 队列长度截断后剩余到期词顺延到次日，不丢失。

## 4.4 主流程四：导入（含全部异常分支）

```text
P08 词单列表 → 目标词单（或先 P11 新建）
   ↓ 点"导入"
P12 导入页（两个 Tab：文件 / 粘贴）
   ├─【文件】
   │   点"选择文件" → 系统文件选择器（UIDocumentPicker，限于 txt/csv/json）
   │     ├─ 用户取消 → 回 P12，不提示错误
   │     ├─ 文件类型不支持 → Toast"暂不支持 .xlsx，请先另存为 CSV"（附格式示例入口）
   │     ├─ 编码非 UTF-8（GB18030）→ 自动转码成功后于预览页提示"已按 GB18030 解码"
   │     └─ 空文件 → 内联错误"文件里没有内容"
   └─【粘贴】
       点"粘贴板" → 读取剪贴板文本 → 直接进入解析
         └─ 剪贴板为空 → Toast"剪贴板里没有文字"
   ↓ 解析
P12-预览
   ├─ 全部行合法 → 显示"共 N 个词，其中 M 个与现有词重复（将跳过）"，前 10 条可滚动预览
   ├─ 部分行非法 → 顶部黄色警告条"第 7、19 行格式不正确，导入时将跳过"（可展开查看原因）
   └─ 全部非法 → 红色空状态 + "查看格式规范"按钮（滚动定位到示例区）
   ↓ 点"确认导入"
P12-成功
   ├─ 按钮区变为"查看词单"（→ P09）与"去学习"（→ P03）
   └─ Toast"已导入 N 个词，跳过 M 个重复，忽略 K 行"
```

## 4.5 主流程五：词根探索

```text
任一入口
 ├─ Tab3 P14 词根库（搜索框 + 按类型筛选：前缀 / 词根 / 后缀）
 ├─ P05 卡片背面点击任一词根色块
 └─ P10 单词详情点击色块
   ↓
P15 词根详情（词根形式 / 中文含义 / 语源 / 记忆提示 / 例词列表 / 同根词）

```

## 4.6 全局回退与死路检查

| 场景 | 回退目标 | 检查结论 |
|---|---|---|
| 学习会话中队列为空（异常） | P06 完成页 | 无死路 |
| 导入全部失败 | P12 保留原始输入，可修改重试 | 无死路 |
| 词单被删后停留在 P09 | 自动返回 P08 | 无死路 |
| 词根详情无例词 | P15 显示"暂无例词，去添加"→ P12 | 无死路 |

| 设置中"每日新词上限"改为 0 以下 | 不允许（步进器下限 5） | 构造上不可能 |

## 4.7 本章小结

- 日常学习主流程为 **3 步点击进入首张卡片**（P01→P03→P04），满足量化目标 G1。
- 异常分支覆盖退出、静默切后台、导入失败、词单删除、数据清空五类，每类均有明确的回退目标页，第 4.6 节逐项核验无死路。
- 复习队列的排序与截断规则被固化在算法内（先复习后新词、最旧到期优先、逾期降档），用户无需理解。

# 第 5 章 页面设计与全部状态 / 交互细节

> 本章为开发实现的直接依据。每个页面按统一结构描述：**用途 → 布局与组件 → 全部状态 → 交互与反馈 → 边界处理**。
> 通用约定（所有页面生效）：① 点击热区 ≥ 44×44 pt；② 所有主操作按钮在拇指区（屏幕下方 1/3）；③ 页面背景使用 `bg` 令牌，卡片使用 `surface` + `cardShadow`；④ 支持系统动态字体，最大放大到 `AX3` 时布局改为纵向堆叠；⑤ 每次页面切换无自定义转场（使用系统默认 push/present），仅页面内元素做微动效。

---

## 5.1 P01 启动页

- **用途**：品牌露出 + 读取本地数据（耗时通常 < 0.1 s，因此启动页目的不是"等"，而是"稳"）。
- **布局**：纯色渐变背景（Brand 渐变 135°），中央垂直居中：App 图标（圆角 22.5% 的方块，内含线性风格 "词根树"图标）+ 名称 "RootWord" + 副标题 "词根单词 · 拆开就记得"；底部不放任何按钮。
- **全部状态**：

| 状态 | 触发条件 | 呈现 |
|---|---|---|
| 正常 | 数据读取完成 | 停留 0.6 s 后自动跳转（首次 → P02，非首次 → P03） |
| 加载慢 | 数据 > 3000 词或旧机型 | 图标下方出现 12 pt 的三点脉冲指示器，最长等待 3 s |
| 数据损坏 | words.json 解析失败 | 停留在启动页，展示卡片："数据文件损坏，已自动备份为 words.bak.json，是否重置为空库？"，按钮"重置并继续"（危险色）/ "稍后处理"（进入只读模式：可查看词单、不可学习） |
| 无存储权限 | Application Support 不可写（理论上不会） | 全屏错误页 + 复制错误码按钮 |

- **交互**：启动页不可点击、不可滑动，避免误操作；不支持点击跳过（时长仅 0.6 s）。
- **边界**：若上一次会话未完成，跳转目标改为 P03 且主按钮文案为"继续学习（还剩 N 张）"。

---

## 5.2 P02 首次引导

- **用途**：用 3 屏建立"这个 App 怎么用"的心智，把三档评分讲清楚（这是唯一需要用户学习的规则）。
- **布局**：横向分页容器（`TabView(.page)` 风格，但用可点击的圆点指示器）；每屏 = 大插图（纯矢量图形，由基础形状绘制，无位图资源）+ 20 pt 半粗标题 + 15 pt 正文（不超过 3 行）；底部固定"继续/开始使用"主按钮；右上角"跳过"文字按钮。
- **三屏内容**：

| 屏 | 标题 | 正文 | 插图形状 |
|---|---|---|---|
| 1 | 只做两件事 | 把单词拆成 前缀 + 词根 + 后缀；在你快忘记的时候提醒你复习 | 一棵由三个色块拼成的树 |
| 2 | 三个按钮，说实话 | 忘记 → 很快再见；模糊 → 明天再见；记得 → 更久以后再见 | 三个圆角按钮的缩略示意 |
| 3 | 把你的词表导进来 | 一行一个单词就能导入；也支持 CSV / JSON | 一张纸 + 向下箭头 |

- **全部状态**：

| 状态 | 触发条件 | 呈现 |
|---|---|---|
| 默认 | 进入 | 第 1 屏，圆点第 1 个高亮，按钮文案"继续" |
| 第 3 屏 | 滑到末屏 | 按钮文案变为"开始使用"，圆点第 3 个高亮 |
| 跳过后 | 点"跳过" | 直接进入 P08（词单列表空状态），后续不再显示引导 |
| 中断 | 滑到第 2 屏时杀掉 App | 下次启动**重新从第 1 屏开始**（引导不记录中间进度，规则简单） |

- **交互**：左右滑动或点击圆点切屏；点"继续"→ 下一屏（带 0.25 s 横向过渡）；点"开始使用"→ 进入 P08；点"跳过"→ 同样进入 P08 但**不标记为已看引导**（下次冷启动仍显示一次，除非完成或跳过第二次）。

---

## 5.3 P03 今日任务（首页）

- **用途**：回答"今天要做什么"，并用一个按钮启动。
- **布局**（自上而下）：
  1. **顶部栏**：左侧无内容；中央标题"今日"；右侧设置图标（仅当无进行中会话时显示）。
  2. **问候语**：`下午好` + 14 pt 次级色日期（如 `9月18日 周五`）。问候语按时间切换：6–11 点"早上好"、11–14"中午好"、14–18"下午好"、其余"晚上好"。
  3. **主进度环**（直径 168 pt）：中心显示"已完成 / 今日总数"，环下方显示"还需 3 分钟"。
  4. **两张数据卡（左右并排）**：`新词 10`（Brand 色）与 `复习 23`（Warning 色），显示数量与"其中 5 个已逾期"副文案（仅当有逾期时出现）。
  5. **主按钮**：全宽 56 pt，"开始学习 · 33 张"。
  6. **次级入口**：一行文字按钮"查看今日词表 →"（进入 P09 的筛选视图）。
  7. 底部 Tab Bar（4 项）。

- **全部状态**：

| 状态 | 触发条件 | 呈现 |
|---|---|---|
| 默认（有待学） | 新词或复习 > 0 | 上述完整布局；进度环显示已完成比例 |
| 空 · 无任何单词 | 词库为空 | 进度环替换为插图（一本书 + 加号）；标题"还没有单词"；副文案"导入你的第一份词表，30 秒开始"；主按钮"导入单词"（→P12）；隐藏新词/复习数据卡 |

| 错误 | 数据读取失败 | 内联错误卡："数据读取失败" + "重试"按钮（重试仅重读一次，不循环） |

- **交互与反馈**：

| 元素 | 点击行为 | 反馈 |
|---|---|---|
| 主按钮 | 装配今日队列 → 进入 P04 | `impactLight` 震动 + 按钮 0.96 缩放 |
| 进度环 | 点击 → 滚动到"今日词表" | 无震动 |
| 新词 / 复习数据卡 | 点击"复习"卡 → 用 `复习` 筛选进入 P09 | 卡片 0.98 缩放 |
| 设置图标 | 进入 P13 | 无 |

## 5.4 P04 学习会话 · 卡片正面

- **用途**：主动回忆。只给最小线索（单词 + 音标），不提前泄露释义。
- **布局**：
  1. **顶部进度条**：细线进度条（高 3 pt，Brand 色）+ 左侧 "12 / 33" 计数 + 右侧"×"退出按钮。
  2. **卡片区**（占屏高约 62%，圆角 24，`surface` 底 + 阴影）：垂直居中排列 —— 单词文本（34–40 pt Bold，超长自动缩小到 24 pt）+ 音标（15 pt 次级色）+ 发音按钮（喇叭图标，28×28 pt 命中区 44×44）。

- **全部状态**：

| 状态 | 触发条件 | 呈现 |
|---|---|---|
| 默认 | 卡片载入 | 单词淡入 0.2 s（透明度 0→1 + 上移 8 pt） |
| 发音中 | 点喇叭 | 喇叭图标切换为"声波"动画（3 条弧线依次点亮，800 ms 循环），按钮禁用防重复 |
| 单词超长 | 长度 > 14 字符 | 字号自动降至 24 pt；仍超出则允许两行并居中；超过 2 行做横向 `minimumScaleFactor(0.6)` 压缩 |
| 无音标 | 导入数据未提供 phonetic | 音标区域不渲染，发音按钮上移对齐（不留空） |
| 复习词 | 该词 `reps > 0` | 卡片右上角显示小色点（掌握度颜色：红/黄/绿），长按显示"已学 3 次 · 下次 6 天后" |

- **边界**：自动朗读开关（设置中无独立开关，默认不自动朗读，防止课堂上突然发声）；静音模式下 TTS 不发声但图标仍反馈（因系统静音不阻断 TTS，此处需主动检测 `AVAudioSession` 类别并遵守静音开关，见第 9 章）。

## 5.5 P05 学习会话 · 卡片背面

- **用途**：给出答案、解释构词、收集记忆强度。
- **布局**（翻转后同卡片容器）：
  1. 顶部保留单词（字号降至 24 pt）+ 音标 + 喇叭。
  2. **释义区**：词性标记（`adj.` 等，小胶囊）+ 中文释义（18 pt，最多 3 行，超出以"…"截断并在点击时展开）。
  3. **词根拆解区**（本产品的核心视觉）：一行色块 chips —— `un-` (前缀·不) `happy` (词根·快乐) `-ness` (后缀·名词化)，三色分别对应 前缀=Info 蓝、词根=Brand 紫、后缀=Success 青；每个 chip 可点击（→P15）。
  4. **记忆法文案**：14 pt，前缀 `💡` 无 emoji，使用图标 + 灰底圆角块，如"un-（不）+ happy（快乐）→ 不快乐的"。
  5. **例句区**：最多 2 条，英文 15 pt + 中文 13 pt 次级色；无例句时整块不渲染。
  6. **底部三档评分按钮行**（核心交互）：三个等宽按钮，高 52 pt，间距 8 pt —— 【忘记】(Danger) / 【模糊】(Warning) / 【记得】(Success)；按钮下方各有一行 11 pt 小字提示下次间隔："10 分钟后" / "1 天后" / "6 天后"（**动态计算**，让用户感知算法的确定性）。
  7. 评分行上方显示当前该词状态："第 3 次学习 · 当前间隔 6 天"。

- **全部状态**：

| 状态 | 触发条件 | 呈现 |
|---|---|---|
| 默认 | 翻转完成 | 内容自上而下 0.2 s 逐块淡入（错峰 40 ms） |
| 无词根数据 | 词根解析未命中 | 拆解区替换为单色 chip（整个单词灰色 + "未收录构词信息"），记忆法块显示导入数据中的 `mnemonic`；两者都无则整块隐藏 |
| 释义超长 | > 60 字 | 显示 3 行 + "展开"，点击后卡片内部滚动（卡片可滚动，评分栏固定） |
| 例句 > 2 条 | 导入多条 | 只显示前 2 条 + "还有 3 条例句"（点击进入 P10 查看全部） |
| 评分中 | 用户点了某一档 | 被点按钮填充实色 + 其他两档淡化 40%，卡片 0.28 s 右滑出（translateX 0→+120%，同时 opacity 1→0） |
| 连续"忘记" 3 次 | 同一词当日第 3 次评分 | 卡片滑出后插入一张**安抚卡**："这个词有点难，先跳过，明天再来"（仅展示 1.2 s 自动继续，不计入评分） |
| 队列仅剩 1 张 | 最后一张 | 进度条显示满格，评分后直接进入 P06（不出现空卡片） |

- **交互与反馈**：

| 元素 | 行为 | 反馈 |
|---|---|---|
| 评分按钮 | 调用 `SRScheduler.rate(word, grade)`，写入 dueAt 与历史 | `impactMedium` 震动（忘记用 `notificationError`，记得用 `notificationSuccess`） |
| 词根 chip | 进入 P15 | 无震动 |
| 释义"展开" | 卡片内滚动 | 无 |
| 点单词 | 再次朗读 | 同 P04 |
| 下滑卡片 | 翻回正面（可回看，不重复朗读不计分） | 反向翻转 0.35 s |

- **边界**：
  - 三档按钮下的小字间隔**必须**来自真实计算（与算法输出一致），不得写死；
  - 若算法输出间隔 > 180 天，显示"180 天后（上限）"；
  - 若该词在自由复习模式，则三档按钮下小字改为"不影响复习计划"，且不写入 SRS。

# 第 6 章 设计规范与视觉语言

## 6.1 设计理念

论断：**"给初中生的极简"不等于"冷淡的性冷淡风"，而是"信息极简 + 情绪明亮"**。落地为三条规则：

| 规则 | 含义 | 具体做法 |
|---|---|---|
| **一屏一件事** | 每个页面只有一个视觉焦点 | 首页只有进度环 + 一个主按钮；学习页只有卡片 + 三个评分按钮 |
| **颜色即语义** | 颜色不装饰，只表达状态 | 三档评分固定为 红/橙/绿，词根三类型固定为 蓝/紫/青，同一含义全 App 同色 |
| **动效只用来解释变化** | 不做无意义动画 | 卡片翻转解释"翻面看答案"；按钮缩放解释"按到了"；数字滚动解释"进度在变" |

## 6.3 字体与字阶

- 字体族：英文/数字 `SF Pro Text / SF Pro Display`（系统默认），中文 `PingFang SC`（系统默认）。**不引入任何自定义字体**（iOS 15.4 环境下自定义字体需打包授权字体文件，增加包体与合规成本）。

|---|---|---|---|---|

| `title1` | 28 | 34 | Bold | 页面大标题（今日/词单/词根） |

## 6.4 间距、圆角与描边

- **间距系统**：4 pt 基准，使用 `4 / 8 / 12 / 16 / 20 / 24 / 32` 七档，禁止出现 5、7、13 等非标值。
- 页面左右安全边距：`20 pt`；卡片内边距：`20 pt`；列表行内边距：水平 20 / 垂直 14（行高 ≥ 56）。
- **圆角**：`chip 10` / `button 14` / `card 20` / `bigCard 24` / `sheet 28` / `sheetTop 28`（仅上圆角）。
- **描边**：`1 pt`，颜色 `border`；仅用于描边按钮与分隔。
- **阴影**：`cardShadow = y:8, blur:24, color: rgba(16,19,25,0.06)`；暗色主题取消阴影，改用 `border` 1 pt 描边（暗色下阴影不可见，避免无效绘制）。

# 第 7 章 艾宾浩斯间隔重复与词根记忆法设计

## 7.1 为什么是 SM-2（而不是自己发明曲线）

艾宾浩斯（Ebbinghaus, 1885）给出的是遗忘**现象**，而非可直接编码的排期算法。SuperMemo 的 SM-2（Wozniak, 1987）是第一个把遗忘曲线工程化为"可复现排期"的公开算法，具备三个适合本产品的特性：**① 只有 3 个状态量（EF / reps / interval）**；**② 是纯函数，可单测、可离线**；**③ 用户只需回答"这次记得怎么样"**。

不自己发明算法的理由：自研曲线无法验证效果，且会把"复习时机"变成不可解释的黑盒，而本产品的核心承诺正是"复习时机绝对正确"。

## 7.2 数据结构

```swift
struct SrsState: Codable, Equatable {
    var ef: Double = 2.5          // 难易因子 Easiness Factor，下限 1.3，上限 2.8
    var reps: Int = 0             // 连续答对次数（"忘记"会归零）
    var lapses: Int = 0           // 累计遗忘次数
    var interval: Int = 0         // 当前间隔（天）；0 表示尚未进入天级间隔
    var dueAt: Date = Date()      // 下次到期时间
    var phase: Phase = .new       // .new / .learning / .review / .relearning / .mastered
    var reinsertCountToday: Int = 0   // 当日在队列中被重插的次数（上限 2）
    var dayKey: String = ""       // 用于重置 reinsertCountToday，格式 yyyy-MM-dd（以 04:00 为日界）
}

enum Phase: String, Codable { case new, learning, review, relearning, mastered }
enum Grade: Int, Codable { case forgot = 1, fuzzy = 3, remembered = 5 }   // 三档评分 → q 值
```

## 7.3 三档评分与参数变化（完整规则）

> **为什么是三档而不是 Anki 的四档？** 四档（Again/Hard/Good/Easy）要求用户区分"困难但答对"与"顺利答对"，初中生在同一张卡片上做这种区分的一致性极低（同一张卡两次会给出不同档位），评分噪声会直接污染 EF。三档（忘记/模糊/记得）语义互斥、彼此可辨，且"忘记"就是"我没想起来"，不存在歧义。代价是间隔梯度变粗，但对 1600 词的初中词表而言，粗梯度足以覆盖。

| 档位 | q | EF 变化 | reps 变化 | interval 变化 | nextDueAt |
|---|---|---|---|---|---|
| **忘记** | 1 | `ef = max(1.3, ef - 0.20)` | `reps = 0`，`lapses += 1` | `interval = 0` | 当日队列重插：`now + 10 分钟`（当日最多 2 次）；超过 2 次 → 次日 04:00 |
| **模糊** | 3 | `ef = max(1.3, ef - 0.14)` | `reps += 1` | `reps==1 → 1`；`reps==2 → 3`；`reps>=3 → round(interval × ef × 0.6)` | 若 `interval==1` 且本次会话内：`now + 10 分钟`（当日再练一次）；否则 `+interval 天` |
| **记得** | 5 | `ef = min(2.8, ef + 0.10)` | `reps += 1` | `reps==1 → 1`；`reps==2 → 6`；`reps>=3 → round(interval × ef)` | `+interval 天` |

**统一收口规则**：

1. `interval = min(interval, 180)`——上限 180 天，避免出现"5 年后再见"的荒诞排期；超过 180 天即视为已掌握。
2. `interval >= 1` 时按天排期，`dueAt = 日历日 + interval`，对齐到当日 **04:00**（日界）。例：今天 9/18 学完，`interval=1` → `dueAt = 9/19 04:00`。
3. **EF 公式的取舍说明**：SM-2 原始公式为 `ef = ef + (0.1 - (5-q) × (0.08 + (5-q) × 0.02))`。对 q=5 得 +0.10、q=3 得 −0.14（本产品直接采用）；对 q=1 原始公式会给出 **−0.54**，三次遗忘即触底 1.3，导致间隔被永久压缩。这对初学者过于严厉，因此**"忘记"档改用固定 −0.20 的惩罚**（已在源码注释与关于页说明中标注为本产品的算法变体，不改名冒称标准 SM-2）。
4. **EF 上限 2.8**：标准 SM-2 无上限，长期全对会使 EF 无界增长，进而使 interval 爆炸。设上限后，连续"记得"的间隔序列收敛为 1 → 6 → 17 → 48 → 134 → 180（见 7.4 验算）。
5. **逾期惩罚**（用户几天没打开）：`逾期 = now - dueAt`。若 `逾期 > 2 × interval`，先降档：`interval = max(1, round(interval × 0.5))`、`reps = max(0, reps - 1)`，再进入本次会话；否则不惩罚，只按正常规则更新。
6. **新词初始化**：`ef = 2.5, reps = 0, interval = 0, dueAt = now, phase = .new`——导入当天即可学。
7. `interval >= 21 天` 时 `phase = .mastered`（"已掌握"口径，用于 G4 与统计页）。

## 7.4 演算验证（可直接作为单元测试用例）

初始：`ef = 2.5, reps = 0, interval = 0, lapses = 0`。日界之后不考虑当日重插。

| 第 n 次评分 | 档位 | ef（评分后） | reps | interval | dueAt 相对今天 | phase |
|---|---|---|---|---|---|---|
| 1 | 记得 | 2.60 | 1 | 1 天 | +1 | learning |
| 2 | 记得 | 2.70 | 2 | 6 天 | +6 | review |
| 3 | 模糊 | 2.56 | 3 | `round(6 × 2.56 × 0.6) = 9` 天 | +9 | review |
| 4 | 记得 | 2.66 | 4 | `round(9 × 2.66) = 24` 天 | +24 | mastered（≥21） |
| 5 | 忘记 | 2.46 | 0 | 0（当日 +10 分钟） | +10 min | relearning |
| 6 | 记得 | 2.56 | 1 | 1 天 | +1 | learning |
| 7 | 记得 | 2.66 | 2 | 6 天 | +6 | review |
| 8 | 记得 | 2.76 | 3 | `round(6 × 2.76) = 17` 天 | +17 | review |
| 9 | 记得 | 2.80（封顶） | 4 | `round(17 × 2.80) = 48` 天 | +48 | mastered |
| 10 | 记得 | 2.80（封顶） | 5 | `round(48 × 2.80) = 134` 天 | +134 | mastered |
| 11 | 记得 | 2.80 | 6 | `round(134 × 2.80) = 375 → 180`（封顶） | +180 | mastered |

序列 1 → 6 → 9 → 24 →（重置）→ 1 → 6 → 17 → 48 → 134 → 180（天），与艾宾浩斯曲线的"先密后疏"形态一致，且全部可复算。

## 7.5 每日队列装配算法

```text
输入：now、settings、全部 Word
输出：有序 CardQueue

1. dayKey = 日历日(now 以 04:00 为界)
2. 对每个 word：若 word.srs.dayKey != dayKey → reinsertCountToday = 0（懒重置，写入时才落盘）
3. dueList   = 所有 dueAt <= now 且 phase != mastered 的词，按 dueAt 升序（最旧优先）
4. newList   = 所有 phase == new 的词，按 (deckId 升序, 词单内 position 升序)，取前 dailyNewLimit 个
5. dueList   = 应用逾期降档规则（7.3 第 5 条），截断到 dailyReviewLimit 个（超出的顺延到次日）
6. queue     = dueList + newList        // 复习在前，新词在后
7. 若 queue 为空 → 首页进入"今日已做完"状态
8. 会话中对"忘记"的词：dueAt = now + 10 min，重新插入 queue 尾部（reinsertCountToday <= 2）
```

约束：队列装配是**确定性**的（同样的输入必得同样的顺序），不引入随机，便于复现问题。

## 7.6 词根记忆法设计

### 7.6.1 词根库数据结构

```swift
struct RootEntry: Codable, Identifiable {
    let id: String            // 唯一 id，如 "un", "spect", "tion"
    let form: String          // 展示形式，如 "un-"、"-tion"
    let normalized: String    // 用于匹配的裸形式，如 "un"、"tion"
    let type: RootType        // .prefix / .root / .suffix
    let meaning: String       // 中文含义，如 "不、否定"
    let origin: String        // 语源，如 "古英语 / 拉丁语 negare"
    let note: String          // 记忆提示
    let examples: [String]    // 例词（单词文本）
}
enum RootType: String, Codable { case prefix, root, suffix }
```

- **库容量**：内置约 120 条，构成为 **前缀 40 条 + 词根 45 条 + 后缀 35 条**，全部选自初中高频构词要素（如 `un- in- im- re- pre- dis- inter- sub- trans-`；`spect port dict duc/duct form ject mit/miss nat pos/poss vid/vis`；`-tion -ment -ness -ful -less -able -er/-or -ist -ity -ous -ive -al -ly`）。
- 库以 `RootLibrary.json` 打进 App 包，只读；用户不编辑（避免脏数据破坏解析稳定性）。

### 7.6.2 词根解析算法（RootParser）

```text
输入：word（原始文本）→ 输出：Segment 序列 + 是否命中

S1 归一化：lowercased()，去除非字母（保留连字符），得到 w
S2 前缀扫描：从 w 头部尝试匹配 prefix 表，按长度 5→2 最长优先；
   支持同化变体：in- 变体 {im-, il-, ir-}，ad- 变体 {ac-, af-, ag-, al-, ap-, ar-, as-, at-}
   命中即记录 (range, rootId)，剩余部分继续
S3 后缀扫描：从剩余部分尾部尝试匹配 suffix 表，同样最长优先；
   支持复合后缀：-ional、-ically、-ations、-ments 视为单条记录（表中显式列出）
S4 词干匹配：剩余中间部分 m 与 root 表匹配，优先级：
   (a) m == normalized                       → 精确命中
   (b) m.contains(normalized) 且 len>=4      → 子串命中
   (c) 编辑距离(m, normalized) <= 1 且 len>=4 → 近似命中（容错 teaching/teach 类变形）
S5 组装：按原文顺序输出 segments；未匹配部分标记 type = .other，meaning = ""
S6 兜底：若整词无任何命中 → 返回"未收录"；App 展示导入数据中的 mnemonic，仍未提供则隐藏拆解区
S7 缓存：解析结果在导入时写入 Word.segments 并持久化，学习时不再重算（保证同一单词展示永远一致）
```

### 7.6.3 解析示例（可作测试用例）

| 输入 | 解析结果 | 拼装文案 |
|---|---|---|
| `unhappy` | `un-`(前缀·不) + `happy`(词根·快乐) | un-（不）+ happy（快乐）→ 不快乐的 |
| `impossible` | `im-`(前缀·不，in- 同化) + `poss`(词根·能够) + `-ible`(后缀·可…的) | im-（不）+ poss（能够）+ -ible（可…的）→ 不可能的 |
| `teacher` | `teach`(词根·教导) + `-er`(后缀·人) | teach（教导）+ -er（人）→ 老师 |
| `international` | `inter-`(前缀·之间) + `nat`(词根·出生) + `-ional`(后缀·…的) | inter-（之间）+ nat（出生）+ -ional（…的）→ 国际的 |
| `spectator` | `spect`(词根·看) + `-ator`(后缀·做…的人) | spect（看）+ -ator（人）→ 观众 |
| `gzzxq` | 未收录 | 显示导入数据中的记忆法（无则隐藏） |

### 7.6.4 记忆法文案生成

优先级从高到低：

1. **导入数据自带** `mnemonic` 字段 → 原样显示（尊重老师/用户自己的记忆法）；
2. **算法拼接生成**：`{f1}（{m1}）+ {f2}（{m2}）… → {word 的中文释义}`，仅当命中 ≥ 2 个片段时生成（只命中 1 个片段时信息量不足，不生成）；
3. 均无 → 隐藏记忆法区块（不留空块）。

### 7.6.5 同根词聚合

- 为每个 `RootEntry` 建立反向索引：`rootId → [wordId]`，导入时增量更新。
- UI 落点：P15 词根详情的例词列表、P10 单词详情的"同根词"横向列表、P15 的"同根词一次学"（把该词根下 `phase != .mastered` 的词全部加入今日队列）。
- 设计意图：把"逐词记忆"变成"记一个词根，通一串词"，这是 G3（24 小时正确率 ≥85%）之外对 G4（30 天 300 词）的直接支撑。

# 第 8 章 单词导入格式规范

## 8.1 设计目标

用户最可能的三种输入姿势：① 从教辅上**手抄**几个词 → 粘贴；② 从 Excel **复制一列** → 粘贴/另存 CSV；③ 老师**发来一个文件**（txt/csv）→ 文件导入。

因此格式规范的第一原则是：**最简可用输入 = 一行一个单词**（只写单词，其余字段全部可选）。

## 8.2 支持格式与识别顺序

| 顺序 | 判断 | 处理 |
|---|---|---|
| 1 | 文件扩展名 `.json` | 按 JSON 解析；失败则报"JSON 格式不正确（第 N 行）" |
| 2 | 文件扩展名 `.csv` | 按 CSV(逗号) 解析；若整表只有 1 列且含制表符 → 回退按 TSV 解析 |
| 3 | 文件扩展名 `.txt` | 按"分隔符自动嗅探"解析（见 8.3） |
| 4 | 粘贴文本（无扩展名） | 同 `.txt` 规则 |
| 5 | 其他扩展名 | 拒绝，Toast"暂不支持 .xlsx，请另存为 CSV 后导入"（`.md`、`.json` 之外一律拒绝） |

编码识别顺序：`UTF-8 (with BOM)` → `UTF-8` → `GB18030`。若三段均解码失败 → 报错"文件编码无法识别，请另存为 UTF-8"。GB18030 回退主要服务 Windows 版 Excel 导出的 CSV。

## 8.3 分隔符嗅探规则（TXT / 粘贴）

按优先级依次尝试，取**首个能保证"每行字段数一致且 ≥1"** 的分隔符：

| 优先级 | 分隔符 | 示例 |
|---|---|---|
| 1 | 制表符 `\t` | `apple\t苹果` |
| 2 | 逗号 `,`（含中文逗号 `，` 归一化） | `apple,苹果` |
| 3 | 竖线 `\|` | `apple\|苹果` |
| 4 | 连续 2 个及以上空格 | `apple    苹果` |
| 5 | 无分隔符（整行即一个单词） | `apple` |

空行、以 `#` 开头的行、以 `//` 开头的行一律忽略（便于用户写注释）。

## 8.4 字段规范

### 8.4.1 字段表（顺序即列序）

| # | 字段名 | 必填 | 类型 | 约束 | 示例 | 缺失时行为 |
|---|---|---|---|---|---|---|
| 1 | `word` | ✅ | 字符串 | 长度 1–32；字符集限 `A-Z a-z - ' 空格`；不含数字 | `unhappy` | 该行报错跳过 |
| 2 | `meaning` | ⬜ | 字符串 | 长度 ≤ 200；超出截断并记警告 | `不快乐的` | 留空显示"—"，不影响学习 |
| 3 | `phonetic` | ⬜ | 字符串 | 长度 ≤ 48；建议含 `/ /` | `/ʌnˈhæpi/` | 不显示音标行 |
| 4 | `pos` | ⬜ | 字符串 | 长度 ≤ 12 | `adj.` | 不显示词性胶囊 |
| 5 | `root` | ⬜ | 字符串 | 形如 `un-+happy`，用 `+` 连接片段 | `un-+happy` | 由本机词根库自动解析 |
| 6 | `mnemonic` | ⬜ | 字符串 | 长度 ≤ 100 | `un（不）+ happy（快乐）` | 由算法生成或隐藏 |
| 7 | `example` | ⬜ | 字符串 | 长度 ≤ 160 | `She looks unhappy today.` | 不显示例句块 |
| 8 | `example_cn` | ⬜ | 字符串 | 长度 ≤ 160 | `她今天看起来不开心。` | 例句下方不显示译文 |
| 9 | `deck` | ⬜ | 字符串 | 长度 ≤ 20 | `七年级上 Unit 3` | 导入到当前选择的词单 |

> 说明：字段顺序固定为 **word → meaning → phonetic → pos → root → mnemonic → example → example_cn → deck**。这是**唯一**的顺序约定；无表头时必须按此顺序。若提供表头，则按表头名映射（见 8.4.2），顺序可任意。

### 8.4.2 表头别名表（CSV / TXT 首行）

| 标准字段 | 可识别的别名（不区分大小写、去空格） |
|---|---|
| word | `word`、`单词`、`词汇`、`英文`、`english`、`en`、`headword` |
| meaning | `meaning`、`释义`、`中文`、`意思`、`翻译`、`translation`、`cn` |
| phonetic | `phonetic`、`音标`、`ipa`、`pronunciation` |
| pos | `pos`、`词性`、`词类` |
| root | `root`、`词根`、`词根词缀`、`拆解` |
| mnemonic | `mnemonic`、`记忆法`、`助记`、`备注` |
| example | `example`、`例句`、`sentence` |
| example_cn | `example_cn`、`例句翻译`、`例句中文`、`sentence_cn` |
| deck | `deck`、`词单`、`单元`、`列表` |

**表头识别规则**：首行若包含任一别名（且不满足 8.4.1 的 `word` 字符集约束，即首行不是合法单词）→ 视为表头，不导入为数据；否则视为数据行。

### 8.4.3 多例句与多释义的分隔

单元格内用 `;`（分号）分隔多条：

- `example` = `She looks unhappy today.;He was unhappy about the result.` → 2 条例句
- `example_cn` 与 `example` 按 `;` 位置一一对应，数量不一致时缺失项留空
- `meaning` 中 `;` 会被合并为 `；`（释义一般不分割，避免误伤）

## 8.6 校验规则与错误分级

| 级别 | 触发条件 | 处理 |
|---|---|---|
| **ERROR（跳过该行）** | `word` 为空 / 含数字 / 长度 > 32 / 含非法字符 | 跳过并记录行号，预览页黄色警告条列出 |
| **ERROR（整体失败）** | 文件 > 5 MB；解析后有效词 0 个；单次导入 > 20000 词；编码无法识别；JSON 语法错误 | 中断导入，展示内联错误与"查看格式规范" |
| **WARNING（保留但提示）** | `meaning` / `example` 超长被截断；`example_cn` 数量与 `example` 不匹配；`root` 字段格式无法识别（忽略该字段，改用自动解析） | 保留数据，预览页提示"第 N 行的释义已截断" |
| **INFO（静默）** | 空行、`#` 注释行、重复行 | 静默忽略，仅在结果中计数 |

### 8.6.1 去重策略

- 去重键：`word.lowercased().trimmingCharacters(in: .whitespaces)`。
- 范围：默认**仅与目标词单内已有词比对**（同一词出现在不同词单是合法的，例如 Unit 3 与 Unit 5 都出现 `happy`）。
- 词单内重复：保留**信息更完整**的一条（按 `meaning > phonetic > example > mnemonic` 字段非空数量排序，多者胜）；若完全相同则保留先出现的。
- 词单间重复：导入预览页提示"另有 3 个词已存在于其他词单（不影响导入）"。
- 导入文件内部重复：同样按 8.6.1 的完整度规则合并。

### 8.6.2 缺失字段的补全链路

```text
word 有、meaning 空
   → 查本机词库其他词单中是否有同名词 → 命中则复制其 meaning（并提示"已从《Unit 1》补全 2 个释义"）
   → 未命中 → meaning 显示 "—"（不编造释义，见写作铁律：不编造内容）

meaning 有、root 空
   → 调用 RootParser 自动解析 → 命中则写入 segments
   → 未命中 → 标记为"未收录构词"，不阻塞使用

root 有、segments 无法匹配词根库
   → 按用户提供的 root 文本原样展示（拆成 chip，类型统一为 other），编辑距离提示"该词根暂未收录"
```

## 8.7 导入流程状态机

```text
Idle
 ├─ 选择文件 → PickingFile
 │     ├─ 取消 → Idle
 │     └─ 选中 → Decoding（编码识别）
 │            ├─ 失败 → FailedEncoding（内联错误，可重试）
 │            └─ 成功 → Parsing
 └─ 粘贴文本 → Parsing

Parsing（按钮显示"解析中…"，禁用）
 ├─ 有效词 = 0 → FailedEmpty（红空状态 + 查看格式规范）
 └─ 有效词 > 0 → Preview（展示统计 + 前 10 条 + 警告行）

Preview
 ├─ 点"返回" → Idle（保留原始输入文本）
 ├─ 点"确认导入" → Importing（>500 词显示进度条，禁用返回）
        ├─ 写入失败 → FailedWrite（Toast"保存失败：存储空间不足"）
        └─ 成功 → Success（统计 + 两个出口按钮）
 └─ 点"查看格式规范" → 滚动定位到内嵌示例区
```

## 8.8 导入结果反馈文案规范

| 结果 | 文案模板 |
|---|---|
| 全部成功 | `已导入 {N} 个词` |
| 有重复跳过 | `已导入 {N} 个词，跳过 {M} 个重复` |
| 有非法行 | `已导入 {N} 个词，忽略 {K} 行格式错误` |
| 组合 | `已导入 {N} 个词，跳过 {M} 个重复，忽略 {K} 行格式错误` |
| 补全 | 追加 `，其中 {P} 个释义从其他词单补全` |
| 上限截断 | `已导入 {N} 个词（受上限 20000 限制，剩余 {R} 个未导入）` |

## 8.9 本章小结

- 最低门槛输入是"一行一个单词"，因此手抄/随手粘贴即可用；字段顺序固定，带表头时按别名映射。
- 校验分 ERROR / WARNING / INFO 三级，非法行跳过但必须报告行号，绝不静默丢弃。
- 缺释义时只做"本地同名词回填"，**不编造释义**；词根缺失时走自动解析，解析不到就明示"未收录"，不使用假数据填充。

## 9.2 iOS 16+ API 禁用清单与替代方案（必守）

> 背景：Xcode 16（iOS 18 SDK）编出、部署目标为 iOS 15 的包，在 iOS 15.4 真机上启动闪退，根因来自两大正交维度：**① 二进制能否在旧运行时跑**（新版 Swift 运行时段 / 新符号 / 被误转强链接的新系统库）；**② TrollStore 让不让跑**（签名与权限）。本章同时处理两者。

| 禁用 API | 引入版本 | 替代方案 |
|---|---|---|
| `NavigationStack` | iOS 16 | `NavigationView` + `NavigationLink(destination:)` 或 `isActive` 绑定 |
| `NavigationSplitView` | iOS 16 | 不需要（仅 iPhone 竖屏） |
| `Charts` 框架 | iOS 16 | 自绘：`Canvas` / `Path` / `GeometryReader` 画柱状图与热力图 |
| `SwiftData` / `@Model` | iOS 17 | `Codable` 结构体 + 手写 `Store` |
| `@Observable` 宏 | iOS 17 | `ObservableObject` + `@Published` |
| `ShareLink` | iOS 16 | `UIActivityViewController` 包一层 `UIViewControllerRepresentable` |
| `presentationDetents` | iOS 16 | 自绘半屏浮层（见 P11） |
| `scrollDismissesKeyboard` | iOS 16 | 点击空白处收键盘（`onTapGesture` + `resignFirstResponder`） |
| `scrollContentBackground` / `.tint()` | iOS 16 | 列表背景用 `.background()`；强调色用 `.accentColor()` |
| `ContentUnavailableView` | iOS 17 | 自绘空状态组件（第 5.18.5 节模板） |
| `Gauge` | iOS 16 | 自绘进度环（`Circle().trim()`） |
| `Grid` | iOS 16 | `LazyVGrid` |
| `ImageRenderer` | iOS 16 | 无需截图能力 |
| `.fontDesign` / `.fontWidth` | iOS 16 | 直接指定 `Font.system(size:weight:design:)` |
| `onChange(of:) { old, new in }` 双参数版 | iOS 17 | 使用单参数旧签名 `onChange(of:) { newValue in }` |
| `.bold()` on Button / `buttonStyle(.borderedProminent)` 的部分参数 | iOS 16 | 用 `buttonStyle(.borderedProminent)`（iOS 15 已支持）或自绘按钮 |
| `AppIntents` / `WidgetKit` 新 API | iOS 16+ | 不做小组件 |
| `BackgroundTask` / `BGTaskScheduler` 新包装 | iOS 16 | 完全不做后台任务 |
| 新 SF Symbols 名称 | iOS 16/17 新增 | 只使用 6.5 节映射表中的符号名，并对每个符号做 `UIImage(systemName:)` 判空兜底 |

| Observation / `@Entry` / 新宏 | iOS 17/18 | 完全不使用宏 |

**编译期防护**：源码不写 `if #available(iOS 16, *)` 分支——一旦写了，就说明有 16+ API 混入，属于禁止项。

## 9.4 零第三方依赖策略

- 不接入 SPM / CocoaPods / Carthage；不拷贝任何第三方 `.framework` / `.xcframework`。
- 理由：① 三方库常引入 iOS 16+ 的 Swift 运行时特性或新版系统库强链接，导致旧运行时 dyld 崩溃；② TrollStore 环境无正式签名，动态库校验风险高；③ 图表、图标、TTS、持久化均已用系统框架覆盖。

## 9.7 TrollStore 安装侧检查清单（iOS 15.4）

| # | 检查项 | 说明 |

| 1 | **已安装 ldid** | TrollStore 设置页执行 `Install ldid`；未装 ldid 会导致重签失败、启动即闪退 |
| 2 | **A12+ 设备禁用 three entitlements** | 不得包含 `com.apple.private.cs.debugger`、`dynamic-codesigning`、`com.apple.private.skip-library-validation`；含则 A12 以上机型必崩 |
